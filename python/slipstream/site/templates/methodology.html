How a run works

Every hour, on the even UTC hour Slipstream buys and on the odd UTC hour it sells, running two order sizes (0.01 and 0.25 BTC) one after another. Each size is executed at the same time with all four strategies (TWAP, VWAP, POV, Almgren-Chriss) against the live public Kraken and Coinbase order books, over 10 minutes. The router splits each strategy's slices across both venues by all-in price (price plus that venue's taker fee), and also prices the same slice on each venue alone, so every run can report what routing actually saved.

What "all-in cost" means

All-in cost is the slippage against the arrival mid-price, plus the exchange's taker fee, in basis points (1 bps = 0.01%). Fees are entry-tier examples (40 bps on Kraken, 60 bps on Coinbase in the current configuration), not the lowest tier either exchange offers at volume.

Known limits

  • Paper trading only. No order placed by this project has ever touched a real exchange account; there is no code path that can.
  • Fills do not consume order-book liquidity. A simulated fill removes nothing from the book that later slices trade against, so a large order can look slightly cheaper here than a real one would be. This is the top item for Phase 2.
  • Only two venues, one symbol. Kraken and Coinbase, BTC/USD.
  • Fee tier is fixed. Real fees vary by 30-day volume and by account.
  • A crash mid-run is recorded, not hidden. A run still "started" when the process ends is marked abandoned on the next hourly run; a run that raises an error is marked failed with that error kept.

Statistics

Every "cheaper" claim on the live page is a bootstrap 95% interval (1,000 resamples, a fixed seed for reproducibility) on the difference of medians. A strategy is only named cheaper when that interval excludes zero; otherwise the page says the comparison is not yet distinguishable, together with the sample size.
